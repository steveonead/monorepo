## §2 架構總覽

### §2.1 層級樹

```
[活動群組（Group）— 選擇性容器，可省略]
  └─ Campaign（廣告活動）
       └─ Line Item / LI（投放項目）
            └─ 素材包（Creative Package，多對多綁定）
                 └─ 個別素材（多筆，唯讀）
```

| 層級              | 預算                         | 走期                           | 自身重點欄位               |
| ----------------- | ---------------------------- | ------------------------------ | -------------------------- |

| 素材包            | —                            | —                              | 廣告格式、包內素材（唯讀） |

## §3 狀態機

### §3.1 狀態定義，Campaign、LI 使用同一組狀態

| 狀態        | 意義                               | 是否投放                   |
| ----------- | ---------------------------------- | -------------------------- |
| `draft`     | 草稿，尚未啟用                     | 否                         |
| `active`    | 啟用中                             | 是（除非被父層遮蔽，見下） |
| `paused`    | 使用者主動暫停                     | 否                         |
| `deleted`   | 軟刪除，UI 不顯示，但資料庫不刪除  | 否                         |
| `completed` | 最終狀態，子層走期到了以後自動收斂 | 否                         |

> 活動群組（Group）無狀態欄位，不參與狀態機。

> 父層遮蔽（Campaign `paused` 時底下 LI 停止投放）為獨立機制，LI 自身狀態欄位不變，詳見 §3.2。

### §3.2 父層遮蔽

- 父層 Campaign `paused` 時，底下子層 LI **實際投放跟著停止**，但 LI **自身狀態欄位不變**
- 當 Campaign `paused` 且 LI `active` 時，LI UI 需提示使用者已受到父層遮蔽。
- Campaign 從 `paused` 恢復 `active` 時，LI 恢復正常投放（LI 自身狀態欄位從未改變），同時對所有儲存狀態為 `active` 的 LI 重新執行 §3.5 啟用條件驗證：
  - 驗證通過 → LI 恢復投放（無狀態變更）
  - 驗證失敗（如素材全被停用）→ LI 從 `active` 降為 `paused`，並跳通知告知原因
  - 儲存狀態為 `paused` / `draft` / `completed` 的 LI：不動
- 廣告素材停用後，若某 LI 的所有綁定素材皆已停用 → 該 LI 自動從 `active` 降為 `paused`，並跳通知。見 §9。

> 活動群組（Group）無狀態，不對子層 Campaign 產生任何遮蔽效果。

### §3.3 狀態轉換規則

Campaign、LI 適用同一組狀態轉換規則：

| from \ to   | active                  | paused           | deleted          | completed |
| ----------- | ----------------------- | ---------------- | ---------------- | --------- |
| `draft`     | ✅ 須通過 §3.5 所有條件 | —                | ✅ dropdown menu | —         |
| `active`    | —                       | ✅ dropdown menu | ✅ dropdown menu | —         |
| `paused`    | ✅ 須通過 §3.5 所有條件 | —                | ✅ dropdown menu | —         |
| `completed` | —                       | —                | —                | —         |
| `deleted`   | —                       | —                | —                | —         |

- `completed` 與 `deleted` 為終態，不可逆
- `active` ↔ `paused` 透過 dropdown menu 切換；`deleted` 是獨立的 kebab menu 操作

### §3.4 completed 的觸發與收斂

- **走期到期自動 completed**：過了 `endDate`，系統自動將該實體設為 `completed` 並**停止投放**。
- **預算花完不等於 completed**（仍在走期內可加預算續跑，語意上屬「停止花費」而非「結束」）。
- **全層對稱自動收斂**：當 Campaign 底下**所有未刪除 LI 都為 `completed`** 時，Campaign 自動 `completed`。
  - **收斂條件**：所有 LI 皆 `completed` 才收斂。只要還有任一 LI 為 `paused`（可能恢復），**不收斂**。
- **`completed` 為最終態**：`completed` 的實體不可再新增子層（Campaign 不可新增 LI、LI 不可新增素材綁定）。

> 活動群組（Group）無狀態，不參與 completed 收斂機制。

### §3.5 啟用實體規則

**啟用 Campaign**，須同時通過：

1. 自身狀態為 `draft` 或 `paused`
2. 預算 > 0
3. **至少一個 LI 存在（不要求 LI 已 active）**
4. 走期 `startDate` / `endDate` 皆已填、且 `endDate ≥ startDate`

**啟用 LI**，須同時通過：

1. 自身狀態為 `draft` 或 `paused`
2. **父層 Campaign 已 `active`**（→ 啟用為 **top-down**：必須先啟用 Campaign，LI 才可啟用）
3. 預算 > 0
4. **至少一個啟用中（active）的素材包已綁定**
5. 自身預算 + 同層 LI 預算加總 ≤ 父層 Campaign 預算
6. 走期 `startDate` / `endDate` 皆已填、且 `endDate ≥ startDate`
7. 啟用 LI 時，**若為 AOE**，`產品線` 不為空

## §4 預算規則

### §4.1 結構：聚合 + 上限混合

| 層級              | 預算模型                                                              |
| ----------------- | --------------------------------------------------------------------- |
| 活動群組（Group） | **Bottom-up 聚合**：= Σ(底下 Campaign budget)，無獨立欄位；選擇性存在 |
| Campaign          | 自設總預算 = 底下 LI 加總的上限                                       |
| LI                | 自設總預算 + 每日預算表                                               |

### §4.2 預算驗證

- **LI 加總 vs Campaign 上限**：任何時候（編輯 / 啟用）只要 LI budget 加總超過 Campaign budget，直接擋住、不給存。
- **Campaign 改總預算時，底下 LI 不自動重分配**：只改變上限，分配權留在 LI 層。改完若 LI 加總超過新上限 → 依上條直接擋（即「改不下去」）。
- **`deleted` LI 不計入加總**；`completed` LI 仍計入 Campaign 預算上限。

### §4.3 每日預算表（LI 層）

- **總預算 = 可分配預算池**；每日預算是它的分配。
- **允許暫時沒分配完**：每日預算加總 **≤** 總預算（差額視為「待分配池」）。
- 每日預算有三種狀態

| 預算值         | 語意               | 「分配剩餘」是否會動它 |
| -------------- | ------------------ | ---------------------- |
| `null`（空白） | 待分配             | ✅ 會被填入            |
| `0`            | 刻意設 0，當天不投 | ❌ 跳過                |
| 正整數         | 已排定金額         | ❌ 保留                |

#### §4.3.1 時間軸鎖定規則

| 區間                 | 規則                                                      |
| -------------------- | --------------------------------------------------------- |
| **過去日**（< 今天） | 完全鎖定，不可改                                          |
| **今日**             | 可調，但**下限 = 今日已花費**（不能調到比今天已花的還低） |
| **未來日**           | 完全可調                                                  |

#### §4.3.2 每日預算動作

- 建立 LI：
  - 總預算**平均攤到走期每一天**，餘數給最後一天
- 修改 LI 總預算時跳出警告，是否要將差額平均分配到今日與未來日，
  - 是：總預算差額平均分配，但今日的**下限 = 今日已花費**
  - 否：總預算差額加入可分配預算池中
- 點擊**釋放預算**：
  - **過去日**預算替換為實際已花費，差額計入可分配預算池
  - **今日**預算替換為實際已花費，差額計入可分配預算池
  - **未來日**預算全部清空（null），退回可分配預算池
- 點擊**均分預算**：
  - 分配預算池 = 總預算 − 過去日已花費加總 − 已排定日（含今日正整數值）
  - 今日同樣參與分配，保底 ≥ `todaySpent`
  - 分配預算池平均分配到預算為 `null` 的日期（含今日），跳過 `0` 與正整數的日期
- **釋放預算** 與 **均分預算** 按鈕僅顯示於 LI 詳情頁，新建頁不顯示。

## §5 走期規則

### §5.1 結構（與預算對稱）

| 層級              | 走期模型                                    |
| ----------------- | ------------------------------------------- |
| 活動群組（Group） | 聚合：所有 Campaign 取 **聯集**；選擇性存在 |
| Campaign          | 自設                                        |
| LI                | 自設，但**必須在 Campaign 走期內**          |

### §5.2 Campaign 改走期

若改 Campaign 走期會使**現有任一 LI 超出範圍**（頭或尾超界），**直接擋住、不給改**（與「預算超上限直接擋」同一套作風）。

### §5.3 LI 改走期 → 跳「預算如何處理」詢問框

`endDate` 最早只能設定為今天，不可回推到過去日。

LI 走期延長或縮短存檔時，**彈出詢問框**，使用者二選一：

| 選項                | 總預算 | 每日表                                                                                 |
| ------------------- | ------ | -------------------------------------------------------------------------------------- |
| **A. 自動重新分配** | 不變   | 重新平均攤到新天數（延長→每天變少；縮短→每天變多），**手動排定值會被重算**             |
| **B. 我自己處理**   | 不變   | 不動：延長→新增日為**空白（待分配）**；縮短→被砍日的錢**退回待分配池**，其餘日原封不動 |

## §6 活動群組（Group）

活動群組是選擇性的 Campaign 分類容器，沒有自身的預算、走期與狀態。使用者可自行決定是否對廣告活動分組，未分組的 Campaign 仍可獨立存在。

### §6.1 建立與管理

活動群組無獨立管理頁面，透過兩個入口操作：

1. **Campaign 建立 / 編輯表單**：「活動群組」欄位為下拉選單，可直接輸入新名稱即時建立 Group，選填。
2. **Campaign 列表 kebab menu**：「移至群組」操作，可指派至現有群組或建立新群組；「從群組移除」可解除關聯。

### §6.2 欄位

| 欄位          | 來源     | 說明                                 |
| ------------- | -------- | ------------------------------------ |
| id            | 系統產生 |                                      |
| 名稱          | 使用者   | 建立或修改時輸入                     |
| 預算          | 自動聚合 | 底下所有 Campaign 預算加總（顯示用） |
| 走期          | 自動聚合 | 底下所有 Campaign 走期聯集（顯示用） |
| Campaign 數量 | 自動計算 |                                      |

## §9 廣告素材

### §9.1 列表頁

顯示所有已被至少一個 LI 綁定的素材包。操作只有開關。

無批次操作。

### §9.2 詳情

素材包由外部系統匯入，本平台無新建素材包 UI；此頁供查閱詳情、管理追蹤碼設定，並檢視包內個別素材。

#### §9.2.3 素材包開關

- 從**素材列表**：點擊開關後，跳出所有綁定該素材包的 LI 選擇框，讓使用者選擇要套用哪些 LI
- 從素材列表觸發時，「只有此素材包的 LI」在 dialog 中**顯示但 disabled**，並附說明「此 LI 只有這個素材包，無法從這裡關閉」。

## §10 追蹤碼模版

### §10.1 設計原則

- 三種實體：**OnePixel**、**CCT**、**第三方量測**
- 只有兩種狀態：**存在**與**已刪除**
- 在 LI 綁定時作為預設值，綁定素材包的時候自動帶入
- 在刪除時，若有 LI 或素材包仍在綁定，系統顯示「共有 N 個綁定將被解除」警告，確認後**自動移除綁定**

### §10.2 OnePixel

OnePixel 是 OneAD 自家的追蹤碼模板，部署於廣告主網站，用於收集第一方事件數據。

#### §10.2.1 欄位

參考 `SuperDSP 1.0`

### §10.3 CCT

CCT Tracker（Cross-Channel Tracker）負責在指定廣告事件發生時，傳送轉換訊號給外部廣告渠道（LINE、Google Ads 等）。

#### §10.3.1 欄位

參考 `SuperDSP 1.0` 與 `ODM`

### §10.4 第三方量測

提供第三方量測廠商的 tracking tag，可掛載至 LI 或個別素材包。

#### §10.4.1 欄位

| 欄位                               | 說明                     |
| ---------------------------------- | ------------------------ |
| `DoubleClick Campaign Manager URL` | DCM 1×1 Pixel 網址       |
| `Nielsen URL`                      | Nielsen 1×1 Pixel 網址   |
| `Integral Ad Science URL`          | IAS JavaScript Tag 網址  |
| `DoubleVerify URL`                 | DoubleVerify JS Tag 網址 |

- 四個欄位至少填一個
- 所有填入的 URL 必須為 HTTPS
