# SuperDSP — 廣告層級核心規格（Campaign / LI / 素材 / 追蹤碼）

> 最後更新：2026-06-05

> 目的：定義 SuperDSP 2.0 廣告層級（Campaign → LI → 素材包）的產品規格。

---

## §0 名詞解釋

| 名詞                     | 說明                                                                                                                                                      |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `OneAD`                  | 公司名稱                                                                                                                                                  |
| `AOE`                    | OneAD 的廣告操作人員                                                                                                                                      |
| `ODM`                    | AOE 目前操作廣告的平台                                                                                                                                    |
| `SuperDSP 1.0`           | 對外開放使用者自己操作廣告投放的平台                                                                                                                      |
| `SuperDSP 2.0`           | **本規格定義的平台**，整合 `ODM` 和 `SuperDSP 1.0` 的平台                                                                                                 |
| `廣告容器`               | 直接含納投放項目、對其施加預算與走期約束的上層實體；**Campaign 為廣告容器**，不是投放開關、不持久化投放狀態                                               |
| `分組 (Group)`           | 使用者**選擇性**用來組織 Campaign 的純檢視／標籤機制；零約束（不帶預算、走期、狀態）                                                                      |
| `儲存狀態`               | 投放項目唯一被持久化的生命週期狀態（draft / active / paused / deleted / completed）                                                                       |
| `有效狀態`               | 由儲存狀態、素材條件、走期、預算即時衍生、用於呈現「實際是否投放」的狀態                                                                                  |
| `素材 (Creative)`        | 個別廣告素材，由外部系統匯入，持自己的審核狀態                                                                                                            |
| `素材包 (Creative Pack)` | 一組素材的**組合**；**LI 綁定的對象是素材包**（非個別素材）                                                                                               |
| `素材包綁定`             | 素材包與 LI 的多對多關聯；與**啟用狀態**是**兩個概念**——綁定分為「掛上／移除」、啟用分為「開（active）／暫停（paused）」，**暫停不解除綁定**（見 §9.2.1） |

## §1 範圍與前提

## §2 架構總覽

### §2.1 層級樹

為對齊第三方平台操作模式，**IO 層併入 Campaign**，階層由四層收斂為三層：

```
[活動群組（Group）— 選擇性容器，可省略]
  └─ Campaign（廣告活動）
       └─ Line Item / LI（投放項目）
            └─ 素材包（Creative Pack，多對多綁定）
                 └─ 個別素材（多筆，唯讀）
```

- **分組 (Group)**：optional，掛在 Campaign 上的純檢視／標籤機制。

### §2.2 各層職責

| 層級     | 預算                    | 走期                 | 自身重點                                                          |
| -------- | ----------------------- | -------------------- | ----------------------------------------------------------------- |
| Campaign | **自設總預算（上限）**  | **自設走期（邊界）** | 廣告容器：持**行銷目標**、對 LI 施加預算/走期約束；**無投放狀態** |
| LI       | 自設總預算 + 每日預算表 | 自設走期             | **唯一投放開關**；持完整儲存狀態與素材包綁定                      |
| 素材包   | —                       | —                    | 廣告格式、廣告預覽、素材時長；由素材組合而成                      |

- 純分類用途由 §6.3 的 optional 分組承擔；Campaign 是廣告容器、不是資料夾。
- 行銷目標由 Campaign 持有（見 §6.2、§6.4）。

## §3 狀態機

### §3.1 狀態定義：**狀態只存在於投放項目（LI）**

廣告容器（Campaign）**沒有投放控制狀態**；下表狀態僅 LI 持有（理由見 §3.2）。

| 狀態        | 意義                              | 是否投放                  |
| ----------- | --------------------------------- | ------------------------- |
| `draft`     | 草稿，尚未啟用                    | 否                        |
| `active`    | 啟用中（投放**意圖**開啟）        | 視有效狀態而定（見 §3.6） |
| `paused`    | 暫停                              | 否                        |
| `deleted`   | 軟刪除，UI 完全不可見、資料庫保留 | 否                        |
| `completed` | 走期已過的儲存終態（凍結）        | 否                        |

### §3.2 廣告容器無自身狀態，但仍呈現兩個衍生資訊

- **Campaign 沒有可切換的投放狀態**（沒有狀態燈、不能手動把 Campaign 設 `active` / `paused`），也沒有父層遮蔽、沒有父層自動收斂、沒有 top-down 啟用。
- **為什麼容器不放狀態**：
  - 父層 `paused` 遮蔽子層，會造成「LI 設了 `active` 卻沒在投、又看不出來」的隱藏落差；
  - 父層恢復時要重驗證、自動降級子層，邏輯複雜且易錯；
  - 容器的職責是**預算上限與走期邊界**，不是投放開關——停止投放的對象是 LI。
- **但「Campaign 沒有狀態」≠「不用顯示任何狀態」**。Campaign 仍須向使用者呈現**兩個衍生資訊**（皆由後端計算後提供前端，使用者不可手動切換）：
  - **已啟用 N 個 LI**：底下儲存狀態為 `active` 的 LI 計數，走期尚未結束時顯示。**此計數由後端算好提供給前端**（前端不自行從 LI 清單湊）。
  - **已完成**：當**今天已超過 Campaign 走期的 `endDate`** 時顯示——**以「今天 vs Campaign 走期」自動計算，不看底下 LI 的狀態**。
- 兩者互斥：**走期內**顯示「已啟用 N 個 LI」、**走期已過**顯示「已完成」。都是衍生值，使用者不能手動切換。狀態一律用「今天有沒有超過 `endDate`」即時算出來，**不要另外存一個狀態欄**（不然跨日忘了更新，顯示和篩選就會跟實際走期對不上）。要存一份來加速也可以，但存的值一定要跟算出來的一樣。

#### §3.2.1 Campaign 走期過後，凍結底下所有 LI 操作

- Campaign 走期一過（`endDate` < 今天），**該 Campaign 底下所有 LI 一律凍結**：不可新增 LI、不可編輯／修改任何 LI（**含 `draft`**）、也**不可刪除**。比官方「completed 不可新增子層」更嚴格——連改、連刪都不行。
- 走期內曾啟用的 LI（`active` / `paused`）會在各自走期到期時自動轉 `completed`（見 §3.6.2）；走期過後仍是 `draft` 的 LI 維持 `draft`、一併凍結（草稿從未投放、不會自動 `completed`）。Campaign 的「已完成」只看走期、與底下 LI 狀態無關（見 §3.2）。
- **要延長走期，必須趕在 Campaign 走期過之前**；走期一過即無法再延長。
- 走期已過的 Campaign **仍可被複製**（即使已衍生為「已完成」），作為「忘記延長走期」的補救出口（重跑路徑見 §6.5.2）。
- 〔後續優化〕可加上「**走期到期前主動提醒**」，提醒使用者及時延長，從源頭減少忘記延長的情況（與 §3.6.1 預算通知同一套機制）。

### §3.3 狀態轉換規則（LI）

| from \ to   | active                  | paused           | deleted       | completed              |
| ----------- | ----------------------- | ---------------- | ------------- | ---------------------- |
| `draft`     | ✅ 須通過 §3.5 所有條件 | —                | ✅ kebab menu | —                      |
| `active`    | —                       | ✅ dropdown menu | ✅ kebab menu | ⤳ 走期到期自動（§3.4） |
| `paused`    | ✅ 須通過 §3.5 所有條件 | —                | ✅ kebab menu | ⤳ 走期到期自動（§3.4） |
| `completed` | —                       | —                | —             | —                      |
| `deleted`   | —                       | —                | —             | —                      |

- `completed` 與 `deleted` 為終態，不可逆。
- `active` ↔ `paused` 透過 dropdown menu 切換；`deleted` 是獨立的 kebab menu 操作。
- **本表為一般規則；Campaign 走期過後另有更嚴格的凍結**：所屬 Campaign 走期一過，底下 LI（含 `draft`）一律凍結，連 `→ deleted` 都不行（見 §3.2.1）。

### §3.4 completed 的觸發（僅 LI，無父層收斂）

- **走期到期自動 completed**：過了 `endDate`，系統自動將該 **LI** 設為 `completed` 並停止投放。
- **預算花完不會變成 `completed`**：只要還在走期內，增加預算就能繼續投放，屬於「暫時停止花費」而不是「走期結束」。預算用完時的處理見 §3.6.1。
- `completed` 是**儲存的終態（凍結依據）**：LI 一旦 `completed`，**不可再改走期 / 預算 / 素材包綁定**；**不可藉延長走期復活**，要再投放需開新的 LI（重跑路徑見 §6.5.2）。
- **無父層自動收斂**：Campaign 的「結束（已完成）」是 §3.2 的**走期衍生**（今天 > Campaign `endDate`），不寫 `completed` 欄位、也不由底下 LI 收斂而來。

### §3.5 啟用 LI 規則

啟用任一 LI，須同時通過：

1. 自身狀態為 `draft` 或 `paused`
2. **Campaign 邊界檢查**：
   - LI 走期需完全落在 Campaign 走期內（不可早於開始、晚於結束）
   - LI 預算加總 ≤ Campaign 上限（`draft` 早已以原訂預算計入加總、見 §4.2；本條僅在啟用同時調高預算時才實際把關）
   - 所屬 Campaign 存在且未刪除
   - Campaign 走期尚未結束（今天 ≤ Campaign `endDate`；走期過後底下 LI 全凍結，見 §3.2.1）
3. 預算 > 0
4. 綁至少一個**可投的素材包**（素材包啟用中、且其底下素材全部審核通過）
5. 走期 `startDate` / `endDate` 皆已填、且 `endDate ≥ startDate`
6. **若為 AOE**，`產品線` 不為空

> Campaign 沒有投放狀態，不擋任何 LI 啟用：啟用只看上面第 2 條的 Campaign 邊界檢查（走期／預算／存在性），不要求「父層已啟用」或「父層至少有一個子項」。

### §3.6 投放狀態怎麼呈現

- LI 的狀態以**單一狀態標籤**呈現，內容就是**儲存狀態**（`draft` / `active` / `paused` / `deleted` / `completed`），代表使用者的投放意圖，由使用者手動切換（兩種由系統自動改的例外見 §3.6.2）。
- 一條 `active` 的 LI 實際是否在投，多數情況與標籤一致；下列情況標籤維持不變：
  - 素材尚未全部審核通過、走期還沒開始、當天每日預算為 0 或尚未分配、投放時段外——這些屬正常排程或良性狀態，標籤不另外標示（走期還沒開始可從「走期」欄看出，或讓標籤顯示為「啟用中（未開始）」變體）。
  - 素材全部無法投放則直接改為 `paused`（見 §3.6.2），不屬於「active 但沒投」。
- **唯一需要特別提醒的例外是「總預算在走期結束前就花完」**（見 §3.6.1）。
- 「有效狀態」作為**內部衍生概念**存在（供 §3.6.1 的提醒判斷、以及 §3.2 Campaign 層「已啟用 N 個 LI／已完成」的衍生使用），不單獨呈現為使用者可見的狀態欄位。

#### §3.6.1 總預算在走期結束前就花完

- 此時 LI 仍維持 `active`（使用者的投放意圖沒變，補預算就會自動恢復投放、不需手動重新啟用），但實際已停止投放。系統**不改儲存狀態**，改以下列方式讓使用者知道：
  - 在該 LI 上**加一個提醒標記**（例如狀態標籤旁的 ⚠ 圖示或「預算已用完」字樣）。
  - **主動發送通知**：「總預算已花完，可考慮補預算」，由使用者決定是否增加預算。
- **補預算仍受 §4.2 上限約束**：調高後若 LI 預算加總超過 Campaign 上限會被擋下，須先擴充 Campaign 上限才補得進去（「自動恢復投放」的前提是補得進預算）。
- 是否發送通知，依「距離走期結束還剩幾天」判斷：
  - 還剩很多天就花完（接下來會有一段不算短的時間完全沒有投放）→ **發送通知**。
  - 已經很接近走期結束才花完（剩沒幾天，等同接近正常結束）→ **不發送通知**，避免每條 LI 快結束時都跳一次提醒。
  - 「剩幾天」的實際門檻，留待實作時再確認。

#### §3.6.2 系統會自動改變儲存狀態的情況（只有兩種）

系統只在下列兩種情況自動改變 LI 的儲存狀態，且每次都會發送通知：

1. **`active` / `paused` → `completed`（走期到期）**：過了 LI 的結束日（`endDate`），不論該 LI 當下是 `active` 或 `paused`，系統皆自動設為 `completed` 並停止投放（`draft` 從未投放，不在此列，維持 `draft`，見 §3.2.1）。`completed` 是終態、不可逆（見 §3.4、§3.3）。
2. **`active` → `paused`（已經沒有任何素材可以投放）**：當一條 LI 最後一個可投放的素材包，因為包內有素材審核不通過而被系統關閉，且這條 LI 沒有其他可投放的素材包時，系統自動把這條 LI 改成 `paused`（見 §9.3）。

> **沒有任何「自動從 `paused` 變回 `active`」的情況。** 不論是上面第 2 點由系統自動暫停、或使用者手動暫停，要再次投放**一律由使用者手動啟用**（並重新通過 §3.5 啟用條件）。§3.6.1 那些情況之所以能「自動恢復投放」，是因為它們從頭到尾儲存狀態都維持 `active`、根本沒被改過，並不是「自動從 `paused` 變回 `active`」。

### §3.7 使用者手動改變 LI 狀態時，系統會做什麼

> 素材包的「啟用 / 暫停」是另一條獨立的軸，記在「LI × 素材包」上，不是 LI 的儲存狀態（見 §9.2.1）。

1. **啟用（`draft` 或 `paused` → `active`）**：系統會先逐項檢查 §3.5 的啟用條件。
   - 全部通過 → 改成 `active`。
   - 有任何一項沒通過 → **維持原狀態不變**，並跳訊息說明還缺哪一項（例如「無法啟用：目前沒有可投放的素材包」）。
   - 一次啟用多條（批次）時：能啟用的就啟用，不能啟用的逐條列出各自的原因，不會因為其中一條失敗就全部失敗。
2. **暫停（`active` → `paused`）**：不需任何條件，一定成功，立即停止投放。暫停只改 LI 的狀態，不會解除任何素材包綁定。
3. **刪除（`draft` / `active` / `paused` → `deleted`）**：透過 kebab menu 操作，為軟刪除——畫面上完全不顯示，但資料庫保留。刪除後這條 LI 不再計入所屬 Campaign 的預算上限與走期約束（見 §4.2、§5.2）。`deleted` 是終態、不可逆。
4. **`completed` 與 `deleted` 無法手動改回其他狀態**：兩者都是終態。需要重新投放時，請另外建立新的 LI。

## §4 預算規則

### §4.1 結構：Campaign 上限 + LI 分配

| 層級     | 預算模型                                    |
| -------- | ------------------------------------------- |
| Campaign | **自設總預算（上限）** = 底下 LI 加總的上限 |
| LI       | 自設總預算 + 每日預算表                     |

### §4.2 預算驗證

- **LI 加總 vs Campaign 上限**：任何時候（編輯 / 啟用）只要 LI budget 加總超過 Campaign 上限，直接擋住、不給存。
- **Campaign 改總預算時，底下 LI 不自動重分配**：只改變上限，分配權留在 LI 層。改完若 LI 加總超過新上限 → 依上條直接擋。
- **佔用範圍**：凡**非 `deleted`** 的 LI 一律以**原訂預算**計入加總（含 **`draft`** 與 `completed`）——「排定即佔用」一以貫之。
- **`deleted` LI 不計入**加總。
- **未花差額不在 Campaign 層回收**：結束 LI 的未花差額不自動退回 Campaign 上限（回收是 LI 內部釋放預算的事，見 §4.3）。要給新 LI 空間，**唯一出口是擴充 Campaign 上限**。
- 取捨：Campaign 帳面已分配額度會與實際花費脫鉤，換得「排定即佔用、結束後金額不再變動」的單純語意。

### §4.3 每日預算表（LI 層）

- **總預算 = 可分配預算池**；每日預算是它的分配。
- **允許暫時沒分配完**：每日預算加總 **≤** 總預算（差額視為「待分配池」）。
- 每日預算有三種狀態

| 預算值         | 語意               | 「分配剩餘」是否會動它 |
| -------------- | ------------------ | ---------------------- |
| `null`（空白） | 待分配             | ✅ 會被填入            |
| `0`            | 刻意設 0，當天不投 | ❌ 跳過                |
| 正整數         | 已排定金額         | ❌ 保留                |

#### §4.3.1 時間軸鎖定規則

| 區間                 | 規則                                                      |
| -------------------- | --------------------------------------------------------- |
| **過去日**（< 今天） | 完全鎖定，不可改                                          |
| **今日**             | 可調，但**下限 = 今日已花費**（不能調到比今天已花的還低） |
| **未來日**           | 完全可調                                                  |

#### §4.3.2 每日預算動作

- 建立 LI：
  - 總預算**平均攤到走期每一天**，餘數給最後一天
- 修改 LI 總預算時跳出警告，是否要將差額平均分配到今日與未來日：
  - 是：總預算差額平均分配，但今日的**下限 = 今日已花費**
  - 否：總預算差額加入可分配預算池中
- 點擊**釋放預算**（差額由使用者以 **checkbox** 勾選要分配到哪些日期）：
  - 使用者以 checkbox **明確勾選**釋放出來的預算要分配到哪些日期；系統**不再自動清空所有未來日**。
  - **使用者已設定的固定預算（正整數）與刻意設的 `0` 不被自動覆蓋**；要分配到 `0` 日需使用者**明確勾選**（勾選＝明確意圖，覆蓋刻意 0）。保護只擋「自動」、不擋「使用者明確操作」。
  - > 不自動清空所有未來日，以免連同刻意設的 `0` 一起抹掉（與「`0` ＝刻意不投」矛盾）。
- 點擊**均分預算**：
  - 分配預算池 = 總預算 − 過去日已花費加總 − 已排定未來日
  - 今日同樣參與分配，保底 ≥ `todaySpent`
  - 分配預算池平均分配到預算為 `null` 的未來日，跳過 `0` 與正整數的日期
- **釋放預算** 與 **均分預算** 僅作用於**單一 LI 內部**的每日預算池，**不影響 Campaign 上限**；按鈕僅顯示於 LI 詳情頁，新建頁不顯示。

## §5 走期規則

### §5.1 結構（與預算對稱）

| 層級     | 走期模型                           |
| -------- | ---------------------------------- |
| Campaign | **自設走期（邊界）**               |
| LI       | 自設，但**必須在 Campaign 走期內** |

### §5.2 Campaign 改走期

- Campaign 走期**恆需涵蓋底下所有非 `deleted` LI** 的走期；改 Campaign 走期若使任一非 `deleted` LI 頭或尾超界 → **直接擋住、不給改**。
- **計入約束的狀態**：`active` / `paused` / `draft` / `completed` 都算；**僅 `deleted` 不算**。
- **`completed` 也約束**：其走期是「真的投過、花過錢」的歷史事實，不允許 Campaign 走期縮到不再涵蓋它（避免投放紀錄落在所屬 Campaign 檔期之外的對帳不一致）。

### §5.3 LI 改走期

`endDate` 最早只能設定為今天，不可回推到過去日；走期需落在 Campaign 走期內（見 §5.1）。

> **要把 LI 走期延長到超出 Campaign 目前走期，必須先延長 Campaign 走期，才改得動 LI**——LI 走期無法單獨超出 Campaign 邊界。同理，Campaign 走期一過便無法再延（見 §3.2.1），延期務必趁 Campaign 走期結束前進行。

走期變更會牽動每日預算分佈（**總預算不變**，走期改的是天數分佈、不是預算池大小）；系統跳出彈窗提醒並確認（二選一）：

| 選項               | 行為                                                                                                                                                                                          |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **去調整每日預算** | 套用走期變更：延長的**新增日預設空白（待分配）**、縮短**砍掉日的預算退回待分配池**；接著**自動捲動到「每日預算」行事曆**，由使用者手動分配（要自動攤平可按行事曆的「均分預算」，見 §4.3.2）。 |
| **取消**           | **放棄這次走期變更**，走期與每日預算都不動。                                                                                                                                                  |

- 每日預算的所有調整（含自動攤平）統一在行事曆操作，不在彈窗內另設分配按鈕——彈窗只負責提醒與導引。
- 僅動 LI 內部的每日預算池，**不影響 Campaign 上限**（見 §4.3）；並遵守 §4.3.1 時間軸鎖定（過去日鎖定、今日下限 = 今日已花費）。
- （**建立 LI 時為例外**：不跳彈窗，總預算自動平均攤到走期每一天、餘數給最後一天，見 §4.3.2。）

### §6.5 複製（Campaign / LI）

複製是「重跑一檔已完成或現有設定」的入口（Campaign 列表 §6.1、LI 巢狀列表 §8.2 的「複製」操作），語意如下：

- **複製出的是全新獨立實體**：Campaign 與底下 LI 都拿到新 id；**花費與成效歸零**，不繼承來源的 `completed` 凍結。
- **狀態**：Campaign 無狀態（不適用）；底下 **LI 一律複製為 `draft`**。`draft` 即不投放——投放閘門在 LI 狀態，使用者須重設走期並逐條手動啟用 LI（§3.5）才會上線。
- **素材包綁定**：一併複製，啟用 toggle 維持初始 **`active`**（同一般綁定，見 §9.2.1）。複製出的 LI 為 `draft`、不會投放，故無須在素材包層另設 `paused`。
- **設定沿用、可改**：行銷目標、預算、走期、分組（Group）等沿用來源值；要重新投放，**須重設走期**（尤其是為了補救「忘記延長走期」的情況）並逐條啟用 LI。
- **不限來源狀態**：即使來源 Campaign 走期已過、衍生為「已完成」，仍可複製（見 §3.2.1）。

#### §6.5.1 是否保留「複製來源」關聯

- **phase0 不建立功能性關聯**：複製＝獨立新實體，與來源各自獨立計算，互不影響（不跨檔彙總預算／走期／成效，也不形成父子關係）。這樣最單純，也避免「來源被刪後關聯懸空」「成效要不要跨檔加總」等連帶問題。
- 〔後續優化〕若日後需要稽核或回溯，可加一個**唯讀的「複製來源」參照**（僅顯示「複製自 Campaign X」），但**不影響任何計算**；phase0 暫不納入。

#### §6.5.2 過期後的重跑路徑（複製是唯一手段，層級對齊過期的層級）

過期（走期到期）的實體一律凍結、不能原地復活——`completed` 的 LI 不可延長走期（§3.4），走期已過的 Campaign 底下全部凍結（§3.2.1）。**要重跑只能用「複製」產生全新實體**；而「該從哪一層複製」取決於**過期發生在哪一層**：

| 過期發生在                                               | 為什麼不能原地復活                | 重跑的正確入口                                                                                  |
| -------------------------------------------------------- | --------------------------------- | ----------------------------------------------------------------------------------------------- |
| **單條 LI**（LI 轉 `completed`，所屬 Campaign 仍走期內） | LI 是終態、不可延走期復活（§3.4） | 在 §8.2 巢狀列表**複製這條 LI** → 得到 `draft` LI、重設走期後啟用。Campaign 未凍結，容得下新 LI |
| **整個 Campaign**（走期已過、衍生「已完成」）            | §3.2.1 把底下**所有** LI 一併凍結 | 在 §6.1 **複製整個 Campaign** → 新 Campaign + 一批 `draft` LI、重設走期後逐條啟用               |

- **核心原則**：被凍結的範圍有多大，就往哪一層複製。LI 過期只凍結那條 LI → 原 Campaign 內複製 LI 即可；Campaign 過期把底下全凍結 → 沒辦法在原 Campaign 複製任何 LI，只能往上複製整個 Campaign（這正是 §3.2.1 所說「忘記延長走期」的補救出口）。
- **連帶規則**：Campaign 走期已過時，**§8.2 LI 列表的「複製」操作一併停用**——它會新增 LI，違反 §3.2.1 凍結（不可新增 LI）。此時該 Campaign 只剩「複製整個 Campaign」這條路。
- 兩種路徑產出的新實體，皆套用 §6.5 的複製語意（新 id、成效歸零、LI 為 `draft`、走期須重設）。

### §6.6 刪除（Campaign）

- **能不能刪，看 Campaign 的衍生狀態（見 §3.2）**：
  - **已完成（走期已過，今天 > `endDate`）→ 不可刪除**：與 §3.2.1 的走期後凍結一致；此時僅能複製（§6.5），不能刪。
  - **走期內 → 可刪除，且為軟刪除**：UI 完全不顯示、資料庫保留（與 LI 軟刪一致，見 §3.7）。
- **連動隱藏、需確認**：軟刪 Campaign 會連同底下 LI 一併從 UI 隱藏；`completed` 的 LI 是終態，維持 `completed`、不被改成 `deleted`（見 §3.3、§3.7）。刪除前跳確認（例「此 Campaign 含 N 個 LI，將一併隱藏」）。
- 〔細節後續實作再定〕：例如底下 `active` LI 連動停投的時機、是否提供復原出口等，phase0 先定語意，細節留待實作。

#### §9.2.1 素材包啟用 / 暫停

- 啟用 / 暫停**只在 LI 詳情頁的素材包區塊**操作（per LI × 素材包）。操作時本就在某條 LI 內，**不需要、也沒有「跳 LI 選擇框」那種畫面**；全域素材包列表（§9.1）為唯讀，不在此切換。
- **綁定時的初始啟用狀態一律為 `active`**（含複製產生的綁定，見 §6.5）：在某條 LI 綁定一個素材包時，該（LI × 素材包）的啟用 toggle 預設為 `active`。素材包 toggle 不是投放閘門——**投放與否由 LI 狀態把關**：LI 為 `draft` / `paused` 時，即使素材包 toggle 為 `active` 也不會投放。
- **暫停 ≠ 移除**：暫停保留綁定；唯一解除綁定的入口是在 LI 內「移除素材包」。
- 「不能停掉某 LI 唯一（可投）素材包」的保護**僅限使用者手動操作**；系統因審核不通過時不受此限（見 §9.3）。

### §9.3 素材審核「通過 → 不通過」的自動處理

前提：**素材包可被選取／投放，需其底下素材全部審核通過**（嚴格衍生：素材包審核＝所有素材皆通過才通過）。

當某素材審核狀態由通過變為不通過時，依序：

1. **(A) 素材包層**：該素材包因「底下有素材不通過」→ 衍生審核轉**不通過** → **不可投**（與綁哪條 LI 無關）。系統並把這個素材包在**所綁的每條 LI 上的啟用 toggle 關閉（設為 `paused`）**——採「暫停」而非「移除綁定」、不自動恢復、不受 §9.2.1 手動保護限制。
2. **(B) LI 層（以 A 為前提，逐條評估）**：對**每條**綁此素材包的 LI，判斷是否還有其他可投素材包：
   - 仍有其他可投素材包 → 該 LI **繼續投放**（不降）。
   - **該 LI 已無任何其他可投素材包** → 該 LI **自動降為 `paused`**。（條件是「沒有別的可投的包了」，不限於「只綁一個包」；綁多個包但全部都不可投時一樣降。）
3. **跳通知**告知：素材審核變動、被關閉啟用的素材包、以及連帶被暫停的 LI。
4. 之後該素材若**重新過審（通過）**，系統**不自動恢復投放**，須由使用者手動開回，分兩層：
   - **素材包啟用**：在所綁的每條 LI 上**維持關閉**，使用者要逐條（per LI × 素材包）手動重新開啟。
   - **LI 狀態**：若該 LI 當初依 (B) 已自動降為 `paused`，**維持 `paused`**（無自動 paused→active，見 §3.6.2），使用者要手動啟用、並重新通過 §3.5（其中「至少一個可投素材包」需先完成上一層的素材包開啟才會成立）。

> **共通原則：追蹤碼與素材的差別**——素材審核不通過會停投（內容合規問題）；追蹤碼只是量測，不影響投放（見 §10.1）。

## §10 追蹤碼模版

### §10.1 設計原則

- 三種實體：**OnePixel**、**CCT**、**第三方量測**
- **三種狀態模型不統一**（分別描述）：
  - **CCT**：我方**主動送出**訊號 → 提供使用者控制的**啟用 / 停用**開關（停用＝暫停送訊號）。這個開關在 **CCT 模板本身**（全域一份），跟「某個素材包綁了哪個 CCT」是兩回事——停用模板，所有用到它的地方都會一起停送訊號。
  - **OnePixel**：部署於廣告主網站、我方只能**觀測** → 狀態為**觀測值（觸發中 / 未觸發，唯讀）**，不提供使用者開關。
  - **第三方量測**：一組 URL → **無狀態**；要停就改 / 移除 URL，不另加開關。
- **共通原則：追蹤碼的啟用 / 停用 / 刪除，只影響「量測」，不影響「投放」。** 停用 CCT ＝停止送訊號但廣告照投；刪除追蹤碼＝解除綁定但廣告照投（皆可能造成成效數據缺漏）。
- CCT / 第三方量測在 LI 設為預設值，帶入素材包（見 §8.3）。
- 刪除時，若有 LI 或素材包仍在綁定，系統顯示「共有 N 個綁定將被解除」警告，確認後**自動移除綁定**。此規則**僅適用 CCT 與第三方量測**（綁 LI／素材包者）；**OnePixel 為 site／廣告主層、不綁 LI／素材包**（見 §10.2），刪除不涉及解除綁定。

### §10.2 OnePixel

OnePixel 是 OneAD 自家的追蹤碼模板，部署於廣告主網站，用於收集第一方事件數據。

- **綁定層級：site／廣告主層、獨立區塊管理，不綁 LI／素材包**（與 CCT／第三方量測不同層，不走 §8.3.1 套用流程）。
- 來源方式（2.0 是平台內建立或外部匯入）**暫不指定**；欄位參考 1.0（見 §10.2.1）。

#### §10.2.1 欄位

參考 `SuperDSP 1.0`

### §10.3 CCT

CCT Tracker（Cross-Channel Tracker）負責在指定廣告事件發生時，傳送轉換訊號給外部廣告渠道（LINE、Google Ads 等）。

#### §10.3.1 欄位

參考 `SuperDSP 1.0` 與 `ODM`

### §10.4 第三方量測

提供第三方量測廠商的 tracking tag。在 LI 設為**預設值**，帶入每個（LI × 素材包）、可逐包覆寫（見 §8.3.1）。

#### §10.4.1 欄位

| 欄位                               | 說明                     |
| ---------------------------------- | ------------------------ |
| `DoubleClick Campaign Manager URL` | DCM 1×1 Pixel 網址       |
| `Nielsen URL`                      | Nielsen 1×1 Pixel 網址   |
| `Integral Ad Science URL`          | IAS JavaScript Tag 網址  |
| `DoubleVerify URL`                 | DoubleVerify JS Tag 網址 |

- 四個欄位至少填一個
- 所有填入的 URL 必須為 HTTPS
