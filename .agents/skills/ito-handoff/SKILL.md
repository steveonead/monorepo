# ito-handoff

## 概覽

將當前對話壓縮成交接文件，讓下一個 session 能完整且快速掌握脈絡並繼續工作。

## 使用時機

- 使用者說「handoff」、「交接」、「幫忙整理給下一個 session」
- 當前 session 即將結束，需要保留工作脈絡
- 呼叫 `/ito-handoff [下一 session 目標或指示]`

**不應使用的情況：** 需要直接實作功能、或只是摘要對話內容（無交接意圖）。

## 核心流程

### 步驟 1：確定存檔路徑

以 `[YYYY-MM-DD-HHmm]-[topic-slug].md` 格式產生檔名，存至 `docs/ito-temp/handoff/`。topic-slug 從對話主題推導（小寫、hyphen 分隔）；若主題不明確，以 `session` 作為 slug。若目錄不存在，先建立。

### 步驟 2：撰寫交接文件

**核心自查問題：** 在寫入每一段資訊前，問自己：「這個資訊能幫助一個對這段對話完全陌生的 session 快速進入狀況嗎，還是雜訊？」確認每一段都有存在必要再保留。

**使用者傳入參數時：** 根據參數決定內容範圍，無關的對話內容捨棄。同時主動判斷哪些是理解該範圍的必要前提，即使使用者未提及也自動納入，接手的 session 沒有前提脈絡無法進入狀況。

**使用者未傳入參數時：** 採最大包含策略，假設任何下一個 session 都可能接手，盡可能保留完整脈絡。

**兩層組織原則：** 當前 session 的性質（討論、實作、診斷等）決定要保留哪些脈絡類型；使用者指定的下一步目標（若有）決定如何組織與強調這些脈絡。

**Artifact 引用：** 不重複貼出現有 artifacts（PRD、計畫、ADR、issue、commit），以路徑或 URL 引用。若某 artifact 的關鍵段落是理解脈絡的必要前提，可摘錄關鍵段落，但需附上完整路徑。

建議下一 session 可用的 skills（若有）。

### 步驟 3：確認存檔

告知使用者交接文件路徑。

## 常見合理化藉口

| 合理化藉口 | 實際情況 |
|---|---|
| 「對話摘要就夠了」 | 摘要缺少脈絡，下一 session 無法判斷哪些決策已確認、哪些待解 |
| 「已有 PRD，不用再寫」 | PRD 記錄需求，handoff 記錄當前工作狀態與未完成事項 |
| 「使用者只要這個部分，其他不用寫」 | 有參數時仍需主動納入必要前提，接手方看不到前提會走彎路 |
| 「artifact 有路徑就夠了」 | 路徑讓接手方再做一輪探索，關鍵段落是必要前提時應摘錄 |
| 「反正要最大包含，什麼都該放」 | 最大包含是無參數時的預設策略，不是不過濾。每段資訊仍需通過自查問題，對陌生 session 無用的就是雜訊 |

## 警訊

- 重複貼出已存在的 artifacts 內容而非引用
- 未告知使用者存檔路徑
- 有參數時未檢查是否需要補充前提脈絡
- 每一段資訊未經自查問題過濾就寫入

## 驗證

- [ ] `docs/ito-temp/handoff/[timestamp]-[slug].md` 已建立
- [ ] 文件涵蓋當前工作狀態與未完成事項
- [ ] 現有 artifacts 以路徑或 URL 引用，關鍵前提段落可摘錄但需附路徑
- [ ] 有參數時：內容聚焦參數範圍，且已補充必要前提脈絡
- [ ] 無參數時：採最大包含策略，脈絡完整
